# 统计分析（第一版）

## 入口与范围

左侧入口顺序：性能诊断 → 统计分析 → 遥控同步。性能诊断保留原开发者诊断功能；统计分析不依赖开发者模式或诊断记录开关。

统计分析有质量监控、性能追踪、行为分析、成本统计四个选项卡，默认打开性能追踪，其他三个显示“开发中”提示（英文为“Under development”）。

## 性能统计口径

- 供应商：按稳定的 `providerId` 汇总该供应商的全部模型调用。
- 模型名：按 `ModelDefinition.modelName` 汇总，跨供应商合并；不使用具体模型的昵称。
- 具体模型：按供应商与 `ModelLink.id` 组合汇总，显示供应商、模型名和具体模型昵称。
- 名称随事件保存；修改配置或删除模型不会改写历史归属。分组使用稳定 ID，供应商或具体模型改名不会拆成两个组；展示该组最后读到的事件名称。旧事件缺少 ID 时才按原有名称回退。

每个实际模型请求尝试（包括重试、模型组故障切换）单独计次。工具调用耗时不计入模型响应耗时；没有结束事件的进行中或崩溃请求不虚构结果。

表格显示有效调用数、成功数、失败数、平均首响、平均完整响应、P50 和 P95。失败包括请求错误、超时和用户中断，不代表任务质量判断。

- 首响：从发出请求到首个有效内容或工具调用增量；不把空的角色增量作为首响，不受 UI 更新节流影响。非流式响应的首响为收到完整有效响应的时间。
- 完整响应：从发出请求到本次模型响应结束，包含流式生成过程，不含请求前的上下文准备、工具执行或事件日志持久化。
- 耗时均值和分位数仅统计成功调用，失败不参与，避免快速报错拉低耗时。没有有效样本时显示 `-`，不填零。首响缺失不推算。
- 分位数采用已排序成功样本的线性插值；样本数由表格成功数标明，小样本不能代表供应商服务承诺。

## 日志与兼容

复用各会话的 `.task-runs.jsonl` 作为唯一事实源，`model-call` 的新字段均可选，兼容原有日志。增加供应商 ID、模型名、模型关联 ID、具体模型昵称、完整耗时和首响耗时，不新增提示词、工具内容或密钥记录。

范围为当前工作区全部已保存项目和会话（包括归档项），删除的会话不参与。打开窗口、切换维度或点击刷新时重新读取，重启后仍可查询；不进行持续轮询。`analytics:performance` IPC 接受维度和可选起止时间；首版界面只展示全部时间范围。

无耗时的旧调用不估算也不回填，界面提示排除数量。损坏/无法读取的日志跳过并显示统计不完整警告，不修复或覆盖原文件。IPC 返回的聚合数据仅含统计维度和数字，不包含事件正文。

## 计费额度不足的排除口径

统计读取时识别失败事件的 reason，覆盖明确的用户额度不足、凭证可用额度用完，以及附带金额证据的预扣费/令牌额度不足。后两类要求剩余金额小于所需金额。仅使用已观察到的报错规则，不根据供应商/模型昵称、HTTP 状态或未经验证的结构化错误码猜测；普通限流、每日请求配额、上下文超限及未知错误仍计入失败。

这些请求同时从有效调用数（totalCalls、sampleCount）和失败数中排除，界面以 excludedQuotaCalls 单独展示排除次数。仅有额度错误的分组不会显示空指标行；全部被排除时仍显示排除数量及空状态。成功调用的耗时口径不变。

先按 runId/callId 去重并应用时间过滤，再识别计费额度；缺少耗时的旧额度错误也记入排除数，不重复计入 skippedCalls。已有日志可直接受益，原始事件不修改、不删除，请求重试和故障转移行为不变。此规则是保守文本识别，未覆盖的措辞继续计入失败，后续依据脱敏样本扩充。测试样本不含真实供应商或模型名。
